# Executive Summary

During continuous monitoring of the Ubuntu endpoint, Wazuh detected an unauthorized modification to a monitored file located inside a protected directory.

The alert was generated by the Syscheck (File Integrity Monitoring) module after the checksum of the monitored file changed. Additional alerts confirmed changes to the file's metadata and permissions.

This scenario reproduces a common post-exploitation technique where an attacker modifies configuration files or application resources after gaining access to a system.

The objective of this investigation was to validate Wazuh's capability to detect, record, and report unauthorized file modifications in real time.

---

# Detection Timeline

## Event 1 — Protected Directory Monitoring

The following directory had previously been configured for real-time monitoring.

```text
/var/www/sensitive
```

Configuration used:

```xml
<directories realtime="yes" report_changes="yes">
/var/www/sensitive
</directories>
```

This enabled immediate detection of any change made within the directory.

---

## Event 2 — File Modification

Observed file:

```text
/var/www/sensitive/config.php
```

Modification performed:

```text
MODIFICATION_DE_TEST_WAZUH=true
```

This simulated an attacker modifying a sensitive application configuration file.

---

## Event 3 — File Integrity Alert

Wazuh immediately generated a File Integrity Monitoring alert.

Rule ID

```
550
```

Description

```
Integrity checksum changed
```

Severity

```
Level 7
```

The alert confirmed that the monitored file had been altered.

---

## Event 4 — Metadata Update

Following the content modification, Wazuh detected additional changes including:

- File size
- Modification timestamp
- Cryptographic checksum
- File attributes

Because `report_changes="yes"` was enabled, the platform also stored the modified content for forensic comparison.

---

## Event 5 — Permission Modification

The following command was executed.

```bash
sudo chmod 600 /var/www/sensitive/config.php
```

Wazuh detected the permission change and updated the file metadata accordingly.

This demonstrates that Syscheck monitors both file contents and security attributes.

# Investigation

The analyst reviewed the alerts generated by the Syscheck module.

The investigation confirmed:

- The monitored file existed before the modification.
- A checksum variation occurred immediately after editing.
- File metadata changed as expected.
- Permission modifications were also detected.
- The alert was generated in real time.

The recorded information was sufficient to reconstruct the sequence of events.

# Root Cause Analysis

Root Cause

A monitored configuration file was intentionally modified during the laboratory exercise to validate Wazuh File Integrity Monitoring.

In a production environment, similar modifications could indicate:

- Web shell installation
- Configuration tampering
- Malware deployment
- Unauthorized application changes
- Persistence mechanisms

# Containment Actions

If this incident occurred in production, the SOC team should:

- Isolate the affected endpoint if necessary.
- Preserve the modified file.
- Compare the modified version with the original.
- Identify the user responsible for the change.
- Review authentication logs.
- Search for additional unauthorized modifications.

---

# Eradication

Possible eradication actions include:

- Restore the original file from backup.
- Remove malicious code.
- Correct file permissions.
- Validate system integrity.
- Scan the endpoint for malware.
- Review persistence mechanisms.

No eradication was required in this laboratory because the modification was intentional.

Recommended recovery activities:

- Continue monitoring the directory.

# Recommendations

To strengthen file integrity monitoring in production:

- Monitor all critical configuration directories.
- Enable `report_changes` for sensitive files.
- Restrict write permissions using the principle of least privilege.
- Regularly review FIM alerts.
- Integrate FIM alerts into incident response procedures.
- Maintain secure backups of critical files.
- Periodically validate file integrity baselines.

---

# Conclusion

This incident response exercise confirmed the effectiveness of Wazuh Syscheck in detecting unauthorized file modifications on a Linux endpoint.

The SIEM immediately identified checksum changes, metadata updates, and permission modifications while preserving valuable forensic evidence for investigation.

In a production SOC, this level of visibility enables analysts to rapidly identify potential post-compromise activity, assess the impact of unauthorized changes, and initiate appropriate containment and recovery procedures before attackers can establish persistence or compromise additional systems.
